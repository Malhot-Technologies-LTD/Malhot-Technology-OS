## Feature module contract

Every `features/<name>/` follows the same shape so any engineer can navigate any feature:

```text
features/tasks/
├── actions.ts        'use server' mutations (thin: parse → authorise → repo → emit → revalidate)
├── queries.ts        server reads (typed selects, rpc calls)
├── repo.ts           write helpers wrapping supabase-js (used only by actions)
├── schemas.ts        Zod schemas shared by forms and actions
├── lib/              pure logic (status machine helpers, cycle detection, health) + unit tests next to them
├── components/       feature UI (server and client components; client files end with .client.tsx)
│   ├── board/
│   ├── task-panel/
│   └── my-tasks/
└── README.md         (optional) only when the feature has non-obvious internals
```

Rules:
- `app/` files are thin: they resolve params, call `queries`, and render `features/*/components`. No business logic in `app/`.
- Features may import from `lib/`, `components/ui`, `components/os`, `hooks/`, `types/`. Features may import from **other features only through their `queries.ts`/`lib/`** (never components or actions), to keep coupling visible. ESLint `import/no-restricted-paths` enforces this.
- `lib/` never imports from `features/`.
- `components/ui` never imports from anything but `lib/utils`.
- Client components are marked at the file level (`'use client'` first line) and named `*.client.tsx` for grep-ability.

## Naming

- Files: `kebab-case.ts(x)`; components exported in PascalCase from kebab-case files.
- Server Actions: verb-first (`createTask`, `updateTaskStatus`, `archiveProject`).
- Queries: `get*` (single), `list*` (many), `count*`.
- Schemas: `<action>Schema` (`createTaskSchema`).
- Database types: `Tables<'tasks'>` from generated types, re-exported as `Task`, `TaskInsert`, `TaskUpdate` in `types/domain.ts`.

## Where things go — quick answers

| Need | Location |
|---|---|
| New page | `app/(os)/os/.../page.tsx` calling a feature component |
| New mutation | `features/<x>/actions.ts` + schema in `schemas.ts` + permission action in `lib/permissions.ts` |
| New table | migration in `supabase/migrations`, regenerate `types/database.ts`, RLS policy, doc update in `docs/database` |
| New event type | `lib/events/types.ts`, SQL rule in `notification_recipients`, renderer in `features/notifications/components` |
| New shadcn component | `npx shadcn add <name>` → `components/ui` |
| New env var | `lib/env.ts` schema + `.env.example` + `docs/engineering/environment-variables.md` |
